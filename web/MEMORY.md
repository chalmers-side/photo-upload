# web

## GOTCHA

- Slideshow `img { max-height: 100% }` does not shrink high-res JPEGs when the frame has no definite height; the photo paints at intrinsic size. Pin the frame with `minmax(0, 1fr)` and position the image with `max-width/max-height: 100%` so it letterboxes and stays centered.
- Do not sweep photos or rebuild `slideshow_q` on every `/api/slideshow` poll. Rebuild on upload, drop, and settings save. Poll only runs the Lua playhead; if the queue is empty but photos exist (first request after deploy), rebuild once.
- `.empty { display: grid }` overrides the `hidden` attribute, so 「尚無照片」 stays on top of real photos. Force `img[hidden], .empty[hidden] { display: none !important }`.
- Slideshow crossfade uses two stacked imgs and `opacity`; do not set `hidden` on them during the transition or `display: none` skips the fade.
- Lottery winner `overflow: hidden` clips the photo shadow into a hard straight edge when the JPEG fills the wrap. Keep the wrap `overflow: visible`. Use `box-shadow` (follows `border-radius`); `filter: drop-shadow` on a JPEG ignores radius and looks square. The 2cm result padding is the room for the blur.
- `Image.save(..., optimize=True)` on phone photos makes upload feel stuck (CPU Huffman pass). Save JPEG at quality 80 with no optimize; `draft()` + bilinear thumbnail for speed.
- Project-home glass looks gray on the first visit because `backdrop-filter` paints before the cover JPEG is decoded (Safari samples an empty layer). Keep a solid frost until `img.decode()`, then add `.is-ready` and turn blur on.
- Slideshow `img { opacity: 0 }` also hides the wall-mode background `<picture>` img. Scope slide rules to `.frame img`.
- Ichiban Kuji panels are glass over the cover glass; the page's own glass and gold button blur through as a smudge. Add `body.panel-open` and hide `.pjt-ui` (`visibility: hidden`) while a panel is open.
- A fourth big button (admin sees 一番賞 + 抽獎) overflowed the home glass at 1280×800. The cover glass (`_cover_layout.html`) is `overflow: auto` so it scrolls inside the glass instead of spilling under the credit.
- Photos uploaded before the person check shipped have no `device_eligible` entry, so they no longer count for the lottery. Reset photos on a live project if that matters.
- Huge uploads look frozen because Pillow `convert("RGB")` materializes the full pixel buffer (HEIC/PNG skip JPEG `draft()`). Shrink in the browser to `JPEG_MAX_EDGE` before XHR, then `thumbnail(..., reducing_gap=2)` before convert. Admin asset `form.submit()` had no pie; use the same XHR overlay as guest upload. Pin the veil on `document.body` at z-index 1000 and paint a frame before shrink. Do not set `.progress-veil { display: grid }` unscoped: it overrides HTML `hidden` and the pie stays up, blocking clicks. Show only with `.is-on`. Overlay CSS lives in `_progress_veil.html` (not `style.css`) so a cached stylesheet cannot hide it. Keep the overlay at least 700ms before reload. After a successful asset POST, `sessionStorage.adminOpenProject` re-opens that project `<details>`.
- Prize-card `img { width/height: 100% }` sizes against the whole card in Safari and paints over the prize name. Keep the JPEG in `.prize-art` (`minmax(0, 1fr)`), center it, and size with `--kuji-prize-fit` (72% mobile / 80% desktop). `max-height: 100%` plus `overflow: hidden` still crops intrinsic-size JPEGs.
- Concatenated `中文 / English` strings cannot be split into a language mode. Keep `config/msg.py` as `(zh, en)` tuples and pick with `g.lang`.
- Kuji sparkles as `position:fixed; z-index:21` sit above the panel glass (`z-index:20`). Safari still hit-tests that canvas on the first tap even with `pointer-events: none`, so 關閉 / 再抽一次 / 我的獎品 do nothing until the second tap. Keep the canvas inside `.tear-scene` and `pointer-events: none !important`. After the peel, `.tear-box.is-open { pointer-events: none }` so the faded ticket does not eat the next click.

## TASTE

- Admin project card is a closed `<details>` by default; summary shows a name link to project home plus a small open-project icon, and copy/QR icons per URL (project, upload, slideshow). After 「更多」: 「重置照片」 (confirm in-page) wipes guest `{32-hex}.jpg` files plus Postgres photos/tickets/lottery_won and the Redis slideshow cache, keeps assets and the project; 「刪除專案」 is left-aligned after that. QR opens a dialog with project name, PNG, and download (`/admin/projects/<id>/qr/<kind>.png`). Asset upload is a single 「上傳」 control: the file picker opens on click and `onchange` submits the form. 「刪除專案」 is ~70% of the old danger button; click reveals in-page 「確認」/「取消」 (no `window.confirm`). Confirm removes the Postgres project (cascade), photo files, and slug URLs (`/p/<slug>/` 404). After 「更多」, assets and knobs sit in four collapsed blocks (首頁 / 輪播 / 抽獎 / 一番賞); each has that page’s images plus its own 參數設定. They store per-project `slideshow_mode` (`wall` or `full`, one at a time), `slideshow_interval`, `slideshow_fade`, `slideshow_queue_max`, `slideshow_per_device`, `lottery_sphere_max`, `lottery_seconds` on the Postgres `projects` row; create copies defaults from `config/appsetting.py`. Interval/fade/queue knobs are shared; only the slideshow layout changes. `wall` is the message-wall (name + caption). `full` is photo-only on cream `#f4efe6`, no background overlay, no 2cm pad, no name/note. `slideshow_fade` is seconds (0–3, default 0.8; 0 = hard cut).

- Fit photos inside the viewport (`object-fit: contain`). Do not set `width/height: 100%` or small photos get stretched.
- Viewport split is repo-wide: Mobile `max-width: 640px` and Desktop `min-width: 641px`. Size knobs live in those two blocks (`--pjt-*` on home, `--glass` on upload/admin/login). Admin asset grid also stacks at 640px. When the user asks to resize UI, ask 手機 or 桌機 first. Cover photos use `<picture>` (`project_home`, `_stage_bg.html` on slideshow/lottery) so only the matching JPEG downloads. Desktop 「開始分享」 lead is 22px; mobile stays 16px.
- Admin, Home, and Back use the stage-card glass (frost fill + `rgba(255,255,255,0.55)` border) and the home 「輪播照片」 type (bold faded ink, `BUTTON_TEXT_FADE`). Size stays `8px 14px` / 14px. Positions are owned by `_admin_chrome.html`: Home centered, Back `top: 12px` left, Admin right, inset `--chrome-inset`. Guests see a Login pill; after login the username pill shows (中文 / English, 改密碼 / 登出). Staff also get Admin as a `.chrome-drop` (帳號管理 `/admin/accounts` for root; 專案管理 `/admin`). Logout is in the username pill and also on the admin list (min-height 44px, `appearance: none`). `/` lists projects: logged-in users see assigned ones (root sees all); anonymous users see slugs in the `visited` cookie (written when opening `/p/<slug>/`). Create project is a `+` overlay on `/admin`; create account is a `+` overlay on `/admin/accounts`. The account page lists every user except root (root gets a lang-only card) and assigns per-project roles plus language. Session stores `user` (username) in a cookie. Roles are per project (`admin` / `maintainer` / `guest`) in Postgres `user_projects`; root is a flag on `users`. First root comes from `ADMIN_USERNAME` / `ADMIN_PASSWORD` via `ensure_root` and is not overwritten. Passwords are Werkzeug hashes. Lottery button and `/p/<slug>/lottery` require a role on that project (including guest). `/admin` requires admin or maintainer on at least one project; `/admin/accounts` is root-only. The project-name open icon is 16px (half of the URL copy/QR buttons). `@ChalmersProduction` is a fixed footer watermark on every page except slideshow (`_credit.html` in `base.html` and `lottery.html`). Slideshow, upload, and lottery use the same pill 「返回 / Back」 top-left to project home (slideshow also honors Escape). On slideshow, Back and Admin fade out after 5s of no mouse movement and return on move (stay visible while the cursor is on them). Bilingual `msg.py` newlines need `white-space: pre-line` (and `|tojson` for JS strings); HTML attributes collapse `\n`. Session cookie is permanent 30 days; `/admin` skips the login form when `session["admin"]` is set.
- Guest upload accepts up to 5 files per submit (`multiple`); admin asset 「上傳」 uses the same overlay (`_progress_veil.html` + `upload_progress.js`). XHR shows a home-style glass overlay inset 2cm with a gold pie + percent (bytes on `xhr.upload`, then 「處理照片中」 until the JSON reply). Oversized files are resized in the browser to `JPEG_MAX_EDGE` (2560) JPEG before send (`pjt-mark` stays PNG). Each saved JPEG adds one lottery ticket. One caption applies to the batch. After `LOTTERY_CHANCE_MAX` (default 10) the flash switches from 「+1」 to the cap copy (keep uploading; slideshow/lottery use latest 10). Lottery uses each device's newest 10 photos; older tickets rotate off. Slideshow queue is a Redis cache rebuilt from Postgres (max `SLIDESHOW_QUEUE_MAX`, default 100). If total photos exceed that, keep each device's newest `SLIDESHOW_PER_DEVICE` (default 5) then the newest 100. Lottery is admin-only. After a draw, that device is added to Postgres `lottery_won` and skipped on later draws and the sphere (the winning spin still includes them). Lottery page bottom-left 「重置抽獎」 (white bold) only deletes that set; tickets and photos stay. Sphere keeps at least 30 photos (pad by repeat). Spin angular speed is exponential decay via rAF (`ω ∝ e^{-kt}`). Winner photo pop and sparkle burst start ~1.1s before the spin duration ends. Winner uses slideshow contain-and-center, inset `LOTTERY_PAD_CM` (default 2cm) from the screen. After the draw, the sides show that device's newest 10 minus the winning photo (max 5 thumbs per side). The congratulations count is the device's total uploads. Click a thumb to preview, centered on the winner photo; the rest of the screen dims ~82%. Click again to close. Sparkles (`web/static/sparkles.js`, preview `sparkle_preview.html`) each travel a great circle: one plane through the sphere center, own tilt/speed/sign. Trails are sampled along that plane (not screen scribbles) so the arc stays planar while photos use the original rotateY/X. After burst, dots ease to a grid and bob vertically. Five even steps from pale gold `#ffe9b0` to silver `#d8dde3`, 20% each. Size is ~2× prior, alpha ≈ 0.2. On win they split to 2500 and burst in the same beat as the winner photo pop (`k=3.2`, ~0.85s), then ease onto a jittered full-screen grid and bob vertically within 0.5cm at staggered slow frequencies. rAF stops on reset or hidden tab. After the draw, top-left Back goes to project home; bottom 「再抽一位」 resets the stage and draws again.

Templates get `msg` from the Flask context processor. Upload labels stay left-aligned (`pre-line` when a side still has a newline). It fades with Back/Admin after 5s idle. Click toggles zoom (`is-zoomed`): hide header pills, drop the chrome pad, `requestFullscreen`. Same pill (「還原」) or Escape exits zoom; a second Escape still leaves to project home. iPhone Safari often ignores fullscreen; hiding the header still fills the page. - Per-project logs go to `LOG_DIR` (`/logs` in the container, `$HOST_PHOTO_DIR/logs` on the host): `<project-id>_yyyyMMdd.log`. Purge uses the date in the filename (not mtime) after 30 days. Button fills: `UPLOAD_BTN_COLOR`, `SLIDESHOW_BTN_COLOR`, `LOTTERY_BTN_COLOR`. Glass padding: `GLASS_PAD_CM` (desktop) and `GLASS_PAD_MOBILE_CM` (≤640px). Upload page edge inset: `UPLOAD_PAD_CM`. The refactor was verified pixel-identical at 390 and 1280 wide.
- Person check: upload stores `person` NULL in Postgres and `LPUSH detect_q`. The detector calls `store.set_person` once per photo (idempotent); a person grants the lottery ticket (`grant_person`, same cap logic). Lottery pool and draw read photos with `person IS TRUE`. Upload JSON returns `photo_ids`; the upload page polls `/api/photos/status` every 1s up to 20s and rewrites the flash.
- Ichiban Kuji: config in Postgres `kuji_config` (`per_user`, A–E totals, display-only Chinese/English labels). Draw is one transaction (`FOR UPDATE` on config). Empty or >40-char side falls back to `{grade}賞` / `Prize {grade}`. Guest UI shows the label for `g.lang` (the other side is still stored). Admin A–E cards keep the grade title and have separate 中文名稱 / 英文名稱 fields. Logged-in root skips the earned/`per_user` cap; sold-out still stops the draw. After the tear, 「再抽一次」 shows when remaining draws (`me.left`) are > 0. Default ticket chrome is CSS (gold/red frame, 一番賞 mark, 米線, serial) — do not copy a BANDAI logo. The draw is recorded before the tear animation, so closing mid-tear keeps the prize.
- Tear peel (`web/static/kuji_tear.js`): fold line is the perpendicular bisector of corner C (bottom-left) and drag point P. Front = rect clipped to the far side (`clip-path` polygon); flap = corner side mirrored with `matrix(I - 2nn^T, 2 d0 n)`, origin `0 0`. Put `clip-path` on the inner element and `drop-shadow` on a wrapper so the shadow follows the clipped shape. Drag only starts near P; release springs back; `P.x >= W` auto-completes. `.prize-card` must `overflow: hidden` and sit at z-index 0 under the ticket, or the prize JPEG and grade paint outside the ticket before the tear (worse on phones). Name sits below `.prize-art`. Mobile `--kuji-grade-size` is 22px (desktop 48px).
- Without Docker: need Postgres plus Redis (or fakeredis for the slideshow Lua), add a `/photos/<path>` route, run the detector in a thread, and drive pages with Playwright (390 and 1280 wide) plus a PIL pixel diff.
